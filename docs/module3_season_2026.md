# М3 — сезон 2026 и интеграция М2 → М3 → М4

Ответственный: Кузнецов Кирилл. Проверка: 28.10.2026.
База: предоставленный архив `precision-ag-stress-detector-main (2).zip`
после обновления М2 (по сообщению команды — PR #9).

## Результат

Обработаны 8 сцен. Сформированы 8 GeoJSON, 8 Shapefile ZIP и 8 JSON-отчётов
в `data/prescriptions/`. Площадь каждой даты — 79,6 га, разброс — 0 га.
Ошибок обработки нет, неполных дат нет. КТ3 и КТ4 М3 проверены на этом
сезоне локально; публикация изменений и командное принятие ещё впереди.

М1 и М2 сохранены без изменений. Для кабинета приложена сопутствующая
правка М4, которую нужно просмотреть ответственному за М4.
Общий `main_pipeline.py` в этом архиве отсутствует: проверен воспроизводимый
запуск `run_real_season.py`, вызывающий М2 и М3, затем кабинет М4.

## Исправленный контракт

- Для kg в `metrics_*.json` добавлены `base_rate_kg_ha`, `price_per_kg`;
  общие `base_rate`, `price_per_unit` сохранены для совместимости.
- Для l используются `base_rate_l_ha`, `price_per_l`; кабинет не подменяет литры килограммами.
- `zone_breakdown[].rate_factor` хранит точный коэффициент (null при нулевой базе).
  Нормы не округляются перед расчётом экономики. Схема JSON расширена совместимо.
- М4 читает обе пары имён, показывает параметры исходных файлов и сумму до копеек.
  За 03.07 при 150/80/0, базе 150 и цене 45: **285 889,50 руб.**
  При 200/100/0, базе 200 и цене 50: **434 550,00 руб.**
  Проверены новые JSON и старые JSON без алиасов и rate_factor.
- Перерасход сохраняется отрицательным. Нулевая база не вызывает деления на ноль.
- Ползунок нормы моделирует пропорциональный пересчёт; если нормы отличаются от
  задания, скачивание старых файлов отключено. Изменение одной цены не блокирует
  скачивание, так как нормы задания остаются прежними. Для новых норм файл
  генерируется повторным вызовом М3. В CLI база сравнения и нормы зон задаются отдельно.

## Облачная дата

18.07 прямые наблюдения покрывают 75,48 га; ещё 4,12 га (412 пикселей, 5,18%)
М2 классифицирует по ближайшей зоне. М3 включает эти классы в предписание и
экономику, поэтому площадь равна 79,6 га. Исходные NaN и растры индексов не
выдаются за измеренные данные. Происхождение заполнения видно в статистике М2,
`input_coverage.json` и предупреждении кабинета.

`coverage` сравнивает классифицированную маску с явным эталонным контуром;
100% покрытия не означает 100% прямых наблюдений. Если в других входах остался
nodata, М3 его не заполняет: исключает из норм и сообщает о неполном покрытии.
Без `--reference-mask` этот дополнительный контроль не выполняется.

## Воспроизведение из корня проекта

```powershell
python -m pip install -r src/module2/requirements.txt -r src/module3/requirements.txt -r src/module4/requirements.txt
python src/module3/examples/run_real_season.py
python -m unittest discover -s src/module3/tests -v
python src/module3/examples/verify_real_season.py
python -m streamlit run src/module4/app.py
```

Первый скрипт выполняет полный сезонный пересчёт М2 → М3. Для новых сцен можно
использовать `stress_core update` по инструкции М2, затем `vra run`.
Воспроизведённый сезон завершается кодом 0. Код 2 у М3 — предупреждение о
нестабильной площади или неполном эталонном покрытии; код 1 — ошибка обработки.
