# Модуль 1. Спутниковые данные: серия чистых сцен Sentinel-2

`s2fetch` по контуру поля и интервалу дат находит сцены Sentinel-2 L2A в Copernicus Data Space (CDSE),
отбрасывает облачные, читает только окно вокруг поля и собирает в `data/scenes/` серию выровненных
файлов `scene_YYYY_MM_DD.tif` для Модуля 2.

Для кабинета М4 `s2fetch.overlays` строит из результатов М2 и сцен окрашенные PNG-слои с координатами углов
(КТ3), а `main_pipeline.py` в корне репозитория прогоняет всю цепочку М1 → М2 → М3 → слои
(см. [`docs/module1_kt3.md`](../../docs/module1_kt3.md)).

Скрипты КТ1 (`search_scenes.py`, `build_sample.py`, `make_field_boundary.py`) остаются как были.
Разбор сезона 2026 и особенности отдельных дат: [`docs/module1_season_2026.md`](../../docs/module1_season_2026.md).

## Установка

Нужны Python 3.11+ и ключи CDSE S3 в `.env` в корне репозитория (`CDSE_S3_ACCESS_KEY`,
`CDSE_S3_SECRET_KEY`, см. `.env.example`). Окружение — `.venv` в корне репозитория.

Arch Linux / Linux / macOS:

```bash
python -m venv .venv
.venv/bin/python -m pip install -r src/module1/requirements.txt
```

Windows (PowerShell):

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r src\module1\requirements.txt
```

Колёса rasterio, lightgbm и opencv для Windows есть на PyPI, GDAL отдельно ставить не нужно.

## Запуск

Команды выполняются из `src/module1`.

```bash
# серия сезона 2026 для команды (8 недель, 07-03 … 08-24)
../../.venv/bin/python -m s2fetch --boundary ../../data/samples/field_boundary.geojson \
    --start 2026-06-29 --end 2026-08-30 --out ../../data/scenes --weekly

# только таблица дат и облачности, без записи файлов
../../.venv/bin/python -m s2fetch --boundary ../../data/samples/field_boundary.geojson \
    --start 2026-05-01 --end 2026-09-30 --out ../../data/scenes --weekly --dry-run
```

PowerShell — то же с `..\..\.venv\Scripts\python.exe`; перенос строки — обратный апостроф:

```powershell
..\..\.venv\Scripts\python.exe -m s2fetch --boundary ..\..\data\samples\field_boundary.geojson `
    --start 2026-06-29 --end 2026-08-30 --out ..\..\data\scenes --weekly
```

| Параметр | Смысл | По умолчанию |
|---|---|---|
| `--boundary` | контур поля, GeoJSON EPSG:4326 | обязателен |
| `--start`, `--end` | интервал дат, включительно | обязательны |
| `--out` | папка сцен | обязателен |
| `--max-cloud` | порог облаков в поле, % | `10` |
| `--weekly` | не больше одной сцены на ISO-неделю (самая чистая; при равенстве — более ранняя) | выкл. |
| `--dry-run` | таблица дат, облачности и пропущенных недель без записи файлов | выкл. |
| `--force` | перезаписать готовые даты (иначе они не перекачиваются) | выкл. |
| `--tile` | плитка MGRS; остальные плитки отбрасываются | `T37TEN` |
| `--dilate` | расширение маски облаков, px | `2` |
| `--reference` | эталон сетки и маски поля; `none` — не сверять | `data/samples/sample_scene.tif` |
| `--manual-masks` | ручные маски облаков/теней; нет файла — пропускается; `none` — не использовать | `src/module1/manual_masks.geojson` |

Для другого поля передайте `--reference none` (эталон относится к полю из `data/samples`).
После правки `manual_masks.geojson` пересоберите затронутые даты с `--force`.

## Как работает

1. **Поиск.** STAC CDSE, коллекции `sentinel-2-l2a` и `sentinel-2-l1c`, по рамке поля. Остаются
   только сцены плитки `--tile`; если на дату несколько версий обработки — самая новая (версия `Nxxxx`,
   затем время обработки). Одна дата — один файл.
2. **Сетка.** Окно по рамке контура с запасом 1 px, привязанное к пикселям B04 плитки (как в КТ1),
   10 м, CRS плитки (UTM). Сетка одна на все даты и сверяется с эталоном: CRS, transform, размер
   (104×104) и маска поля (7960 px). При расхождении запуск прекращается до записи файлов.
3. **Облака.** Внутри контура:
   - SCL 0 (нет данных) или 1 (дефект) > 10 % поля — сцена отбрасывается («нет покрытия»); меньше — эти пиксели в NaN;
   - SCL 3, 8, 9, 10 (тени, облака, перистые);
   - s2cloudless по L1C той же съёмки (B01, B02, B04, B05, B08, B8A, B09, B10, B11, B12; минус смещение
     1000 для N0400+; `threshold=0.4`, `average_over=22`, окно с запасом 500 м). Если L1C нет или он не
     читается — запасной вариант MSK_CLDPRB ≥ 40 % из L2A (что использовано — в теге `cloud_mask`);
   - ручные полигоны своей даты из `manual_masks.geojson`.

   Сцена отбрасывается, если объединение (без расширения) > `--max-cloud` % поля. В принятой сцене
   объединение расширяется на `--dilate` px и становится NaN.
4. **Каналы.** `WarpedVRT` по `/vsis3/` читает только нужные блоки; 20-метровые каналы (B05, B06, B07,
   B8A, B11, B12) — bilinear на сетку 10 м (то же, что `rasterio.warp.reproject`). Отражение =
   `max(DN − смещение, 1) / 10000`, смещение 1000 для обработки N0400+.
5. **Повторы.** STAC — до 6 повторов с паузой при 429/5xx, GDAL — 5 повторов HTTP, чтение канала — до
   4 попыток с паузой 10/20/30 с. Ошибка одной даты попадает в манифест и не обрывает серию.

## Формат выхода

`data/scenes/scene_YYYY_MM_DD.tif`:

- GeoTIFF float32, 10 каналов: `B02, B03, B04, B05, B06, B07, B08, B8A, B11, B12` (описания каналов
  записаны, Модуль 2 берёт порядок по ним), отражение 0..1;
- `0` во всех каналах — вне контура поля (`nodata=0`), одна и та же маска на всех датах;
- `NaN` во всех каналах — облако/тень/нет данных внутри контура;
- сжатие deflate, CRS EPSG:32637, сетка как у `data/samples/sample_scene.tif`;
- теги: `date`, `source` (id L2A), `l1c_source`, `scale=reflectance`, `boa_offset_removed`,
  `cloud_percent_in_field` (итоговая доля NaN), `scl_cloud_percent`, `union_cloud_percent`,
  `manual_mask_percent`, `cloud_mask` (чем маскировали), `tile`.

`data/scenes/scenes_manifest.json` — параметры запуска, сетка и по каждой найденной дате: id L2A и L1C,
доли (`invalid_percent`, `scl_cloud_percent`, `union_cloud_percent`, `manual_mask_percent`,
`nan_percent`), принята/выбрана, причина, статус. Записи дат вне текущего интервала из прошлых
запусков сохраняются. Пути `boundary` и `manual_masks` записываются относительно папки манифеста, с «/»
(абсолютные — только если относительного пути нет, например контур на другом диске Windows).

`data/scenes/preview/scene_YYYY_MM_DD.png` — RGB | NDVI | маска (жёлтый — SCL, пурпурный —
s2cloudless, оранжевый — ручная маска, голубой — расширение), `all_dates.png` — все даты. В git не
хранятся. Для отброшенных только s2cloudless/ручной маской дат — `preview/rejected/`.

## Слои для кабинета М4 (`s2fetch.overlays`, КТ3)

```bash
../../.venv/bin/python -m s2fetch.overlays --data ../../data            # data/overlays/*.png + meta.json
../../.venv/bin/python tools/overlay_map.py --data ../../data --date 2026_07_18 --show RGB   # overlay_check.html
../../.venv/bin/python tools/check_m4.py ../../data --expect-dates 8    # кабинет М4 через AppTest
```

| Параметр | Смысл | По умолчанию |
|---|---|---|
| `--data` | папка данных (нужны `stats/`, `indices/`, `zones/`, `scenes/`) | `../../data` |
| `--nodata-mode` | облако/тень внутри поля: `gray` — серый «нет данных», `transparent` — прозрачно | `gray` |
| `--oversample` | выходных пикселей PNG на пиксель 10 м | `8` |
| `--no-hidden` | не строить `HIDDEN_*.png` | выкл. |
| `--force` | перерисовать, даже если входы не менялись | выкл. |

- Слои: `NDVI`, `NDRE`, `MSAVI`, `NDMI` — из растров индексов М2 (сами индексы не пересчитываются),
  `RGB` — true color из сцены (B04, B03, B02), непрозрачный (alpha 255). Растяжка своя, не как у превью КТ2:
  перцентили 2 и 98 отражения трёх каналов вместе по пикселям поля всех дат сезона (сейчас 0,0242…0,0880),
  гамма 1,3. Одна шкала на три канала сохраняет баланс цвета (по каналам — пурпурный оттенок на колее),
  одна на сезон — даты сравнимы между собой;
  `HIDDEN` — маска скрытого стресса М2 (М4 её пока не показывает).
- Сетка PNG — EPSG:3857, около 8 выходных пикселей на пиксель 10 м (PNG 846×849), метод nearest: пиксели
  остаются чёткими квадратами. Сетка UTM относительно 3857 повёрнута на −0,96°, масштаб ≈1,475 (метров 3857 на метр UTM в центре поля).
  `meta.bounds` — lat/lon углов прямоугольника 3857, одни на все даты и слои.
- Палитры индексов, альфа 235 и шкала — ровно как в `src/module4/app.py` (`colorize`, `season_ranges`), тест сверяет
  их через `ast`. Шкала зависит от всех дат, поэтому при изменении любого входа перерисовываются все PNG;
  если входы не менялись, файлы не трогаются.
- Вне контура — прозрачно; облако/тень внутри контура — серый `[128,128,128,150]`, чтобы сквозь дыру не была
  видна подложка Esri другой даты.

Контракт `overlays/meta.json` — в [`data/README.md`](../../data/README.md).

## Ручные маски

`src/module1/manual_masks.geojson` — облака и тени, которые не поймали автоматические маски.
`crs` в файле: `urn:ogc:def:crs:EPSG::32637` или EPSG:4326 (`CRS84`, по умолчанию). Свойства
полигона: `date` (YYYY-MM-DD), `kind` (`cloud` | `shadow`), `note`. Пиксель маскируется, если его
центр внутри полигона. Кандидатов можно найти диагностикой:

```bash
../../.venv/bin/python tools/temporal_cloud_check.py ../../data/scenes --geojson candidates.geojson
```

Она сравнивает каждую дату с соседними и ничего в сценах не меняет (подробнее и почему не встроена —
в `docs/module1_season_2026.md`).

## Ограничения

- **s2cloudless здесь почти ничего не добавляет к SCL.** Он не видит перистые облака и тени, которые
  SCL отмечает (классы 10 и 3), а мелкие низкие облака сглаживает (`average_over=22` при 10 м). Пример
  такого облака — 2026-07-18, закрыто ручной маской.
- Дымку (2026-07-08) маска не убирает: она однородная, Sen2Cor её частично корректирует.
- Тень облака, которое за пределами окна поля, автоматически не находится.
- Перекрытие соседних плиток другой зоны UTM отбрасывается: сетка задана в UTM 37N.
- Порог 10 % считается до расширения, поэтому итоговая доля NaN может быть немного больше 10 %.
- Повторный запуск без `--force` не пересобирает готовые даты, даже если поменялись маски или параметры.
- Повторный запуск со скачиванием заново оценивает облачность всех дат интервала по CDSE (~2 мин), даже
  если новых сцен нет; файлы при этом не меняются.
- Тайлового сервера (TiTiler) нет: кабинет получает готовые PNG.
