# Модуль 2. Аналитическое ядро: спектральные индексы и сегментация стресса

Вход: многоканальные GeoTIFF-сцены (`scene_YYYY_MM_DD.tif`, отражение, по одной на дату).
Выход: маски зон `zones_YYYY_MM_DD.tif` (0 фон, 1 сильный стресс, 2 умеренный, 3 норма), файлы индексов,
`index_stats_YYYY_MM_DD.json` на каждую дату (для дашборда M4) и сводный `indices_summary.json`.

## Запуск

Команды выполняются из папки `src/module2` (рядом с `stress_core/`).

```bash
pip install -r requirements.txt     # numpy, scipy, scikit-learn, tifffile, imagecodecs
pip install spyndex                 # опционально (бэкенд spyndex и сверка формул)

# серия сцен -> data/zones, data/stats, data/indices, data/hidden_stress
python -m stress_core run ../../data/scenes -o ../../data

# одна сцена: каналы и дата берутся из файла (у sample_scene.tif дата записана в метаданных)
python -m stress_core run ../../data/samples/sample_scene.tif -o out

# только индексы одной сцены: NDVI.tif, NDRE.tif, MSAVI.tif, NDMI.tif
python -m stress_core indices ../../data/samples/sample_scene.tif -o out_indices

# демо на синтетическом поле (3 даты)
python -m stress_core demo -o demo_out
```

Папки `out`, `out_indices`, `demo_out` не коммитьте: это результаты запуска.

**Каналы** определяются по файлу: по описаниям B02…B12, которые пишет M1; без описаний 10 каналов считаются форматом M1
(`B,G,R,RE1,RE2,RE3,N,N2,S1,S2`), 4 канала — `R,RE1,N,S1`. Вручную: `--bands s2-10` или имена ASI через запятую.
Если заданный порядок не совпадает с числом каналов или с описаниями в файле, это ошибка (перепутанные каналы иначе
молча дали бы неверные индексы). **Дата** берётся из `--date`, иначе из имени файла, иначе из тега `date` в метаданных.
`--classes 3|4|5|auto`, по умолчанию 3 (контракт M2 -> M3).

Тесты: `python -m unittest discover -s tests -v` (из `src/module2`).

## Интеграция в общий пайплайн (для `main_pipeline.py` модуля 1)

Для каждой новой даты достаточно одного вызова:

```python
from stress_core import analyze_field

rec = analyze_field("data/scenes/scene_2026_08_14.tif")
# -> data/zones/zones_2026_08_14.tif, data/stats/index_stats_2026_08_14.json, data/indices/*, data/hidden_stress/*
```

- **Куда пишет.** Для сцены из `data/scenes/` результаты по умолчанию ложатся в `data/` (раскладка из плана); можно передать папку вторым аргументом.
- **Динамика между датами.** Если в `data/indices/` уже лежат результаты более ранней даты, `analyze_field` сравнивает новую сцену с ближайшей предыдущей (дата сравнения записана в `early_stress.compared_with`; `null`, если сравнивать не с чем или сетка другая). Результат совпадает с обработкой всей серии за один запуск (проверено тестом).
- **Серия целиком:** `python -m stress_core run data/scenes -o data`. Файлы без даты и повторы даты пропускаются с предупреждением (список в `indices_summary.json`, поле `warnings`). Флаг `--no-history` отключает сравнение первой сцены с уже имеющимися результатами.
- `indices_summary.json` дополняется: даты, обработанные в прошлых запусках, сохраняются.
- Ошибка в одной сцене не останавливает серию: в `indices_summary.json` у даты будет поле `error`; `analyze_field` для одной сцены при ошибке выбрасывает `RuntimeError`.

## Контракт входа

- GeoTIFF; uint16 = отражение ×10000, float32 = отражение 0..1 (как в плане M1). Если float-значения явно больше 1 (не нормированы), делитель 10000 выбирается сам; вручную `--scale`. Выбранные порядок каналов и делитель записываются в `index_stats` (поле `input`).
- Сжатие: deflate/zstd или без сжатия читаются всегда; LZW, JPEG и float-предиктор требуют `imagecodecs` (есть в `requirements.txt`).
- Пиксели вне поля — nodata (0 или NaN) во всех каналах, облака и тени замаскированы **до** модуля (NaN или nodata). Валиден пиксель, где все нужные каналы конечны и `0 < отражение <= 1.5`.
- Все каналы на одной сетке 10 м (ресемплинг — задача M1), CRS проекционная в метрах (UTM), иначе `area_ha` будет `null`. Для сравнения дат сетка должна совпадать.

## Контракт выхода (`<out>/`)

| Файл | Содержимое |
|---|---|
| `zones/zones_YYYY_MM_DD.tif` | uint8: `0` нет данных, `1` сильный стресс (худший по NDRE), `2` умеренный, `3` норма. Для M3 нужны 3 класса (по умолчанию) |
| `stats/index_stats_YYYY_MM_DD.json` | статистика даты и `early_stress_alert` (см. ниже) |
| `indices/NDVI_YYYY_MM_DD.tif` (+ `NDRE`, `MSAVI`, `NDMI`) | одноканальные float32, NaN = нет данных |
| `hidden_stress/hidden_stress_YYYY_MM_DD.tif` | uint8: `1` скрытый стресс, `0` нет, `255` нет данных |
| `indices_summary.json` | то же по всем датам, плюс конфигурация запуска и предупреждения |

Геопривязка (CRS, шаг, начало координат) копируется из входной сцены.

**`index_stats_YYYY_MM_DD.json`.** Поля для дашборда: `date`, `mean_ndvi`, `mean_ndre`, `mean_msavi`, `mean_ndmi`,
`early_stress_alert` (bool), `early_stress_area_ha`, `early_stress_percent`, `field_area_ha`. Дополнительно: `grid`, `valid_pixels`,
`indices.<имя>` (`n, mean, std, min, max, p5…p95`), `zones` (`n_classes`, `classes[]` с `class, label, pixels, fraction, area_ha, mean{индекс}`),
`hidden_stress`, `early_stress` (`alert`, `reasons`, `ndre_drop`, `ndvi_drop`, `common_fraction`, `compared_with`), `input` (`band_order`, `band_names_in_file`, `scale`, `dtype`), `files`.
`mean_*` — средние по всем пикселям поля на эту дату; `ndre_drop`/`ndvi_drop` — изменение относительно прошлой даты по пикселям, видимым на обеих датах.

## Как это работает

1. **Индексы** (`indices.py`): NDVI, NDRE, MSAVI2 (в файлах и ключах `MSAVI` / `mean_msavi`), NDMI по формулам каталога Awesome Spectral Indices; значения сверены со spyndex тестом `test_matches_spyndex`.
2. **Скрытый стресс** (`early_stress.py`): NDRE и NDVI сглаживаются (σ=1 px), переводятся в робастный z-score относительно самого поля. Флаг — NDRE заметно ниже нормы (`z <= -1.5`) при ещё нормальном NDVI (`z > -1.0`). Если есть предыдущая дата, добавляется временное условие: падение аномалии NDRE между датами при почти неизменной аномалии NDVI. Мелкие пятна (< 12 px) убираются.
3. **`early_stress_alert`**: `true`, если скрытый стресс занимает не менее 1% поля, либо (при наличии прошлой даты) NDRE упал минимум на 0.02 и относительно быстрее NDVI в 1.5 раза и более. Падение считается только по пикселям, видимым на обеих датах (облако на одной из дат иначе сдвигает среднее и даёт ложную тревогу); если таких пикселей меньше 50%, динамика не оценивается. Пороги в `EarlyStressConfig`.
4. **Зоны** (`zoning.py`): признаки (NDVI, NDRE, MSAVI2, NDMI) сглаживаются и стандартизируются, KMeans (k задан или по силуэту в 3–5), классы сортируются по среднему NDRE (1 — самый низкий), затем мажоритарный фильтр (как `median_filter` в ТЗ, но для меток классов) и слияние пятен < 25 px с соседом.
5. **Края поля.** Пиксели на границе поля и у дыр от облаков смешанные (часть пикселя занимает дорога или соседний объект) и выглядят как ложный стресс. Пояс шириной `edge_buffer_px` (по умолчанию 1 px) не участвует ни в кластеризации, ни в поиске скрытого стресса. В маске зон такие пиксели получают класс ближайшей зоны, поэтому контур и площадь поля не меняются. Отключается `edge_buffer_px=0` в `ZoningConfig` и `EarlyStressConfig`. Статистика индексов в JSON по-прежнему считается по всем пикселям поля.

## Ограничения и допущения

- **Зоны относительные.** Класс 1 — «хуже остального поля на эту дату», а не абсолютный порог. На здоровом поле алгоритм всё равно выделит классы из-за неоднородности почвы, поэтому подписи читайте вместе со средними индексами класса. Смысл номера класса между датами не гарантирован.
- **Скрытый стресс тоже относительный:** если угнетена больше половины поля, медиана смещается и метод занижает очаги.
- Пороги (`EarlyStressConfig`, в том числе пороги тревоги) подобраны на синтетике и одной реальной сцене, на полевой разметке **не калибровались**. Динамика между датами проверена только на синтетических сериях.
- Пояс шириной 1 px по краю поля не классифицируется сам, а наследует класс соседей: реальный очаг шириной в один пиксель у самой границы будет сглажен.
- Xarray и rasterio не используются: расчёт на NumPy, GeoTIFF через tifffile. Повёрнутые растры (ModelTransformation без шага пикселя) читаются, но площадь для них не считается.
- Бэкенд `spyndex` (`--backend spyndex`) проверен тестом на машине автора; в окружении без пакета тест пропускается.
