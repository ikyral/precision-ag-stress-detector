# Модуль 2. Аналитическое ядро: спектральные индексы и сегментация стресса

Вход: многоканальные GeoTIFF-сцены (отражение, по одной на дату).
Выход: растровые маски зон (GeoTIFF, классы 1..N), маски скрытого стресса и сводный `indices_summary.json`.

## Запуск

```bash
pip install numpy scipy scikit-learn tifffile      # обязательные
pip install spyndex                                 # опционально (перекрёстная проверка индексов)

# демо на синтетическом поле (3 даты)
python -m stress_core demo -o demo_out --save-indices

# свои сцены: файлы или папка, дата YYYY-MM-DD (или YYYYMMDD) в имени файла
python -m stress_core run scenes/ -o out --bands R,RE1,N,S1                  # 3 класса по умолчанию; --classes 4|5|auto
# 10-канальная сцена Sentinel-2 из data/samples (имя файла должно содержать дату, напр. scene_2026_08_07.tif):
python -m stress_core run scene_2026_08_07.tif -o out --bands B,G,R,RE1,RE2,RE3,N,N2,S1,S2
```

Из Python:

```python
from stress_core import run_pipeline, ZoningConfig, EarlyStressConfig
summary = run_pipeline(["scenes/"], "out", zoning_cfg=ZoningConfig(n_classes=4))
```

Тесты: `PYTHONPATH=. python -m unittest discover -s tests -v`

## Контракт входа

- GeoTIFF, каналы идут в порядке `--bands` (по умолчанию `R,RE1,N,S1` = Sentinel-2 B04, B05, B08, B11).
- Целочисленные файлы делятся на 10000 (меняется через `--scale`), float считается отражением 0..1.
- Облака/тени должны быть замаскированы **до** модуля (NaN или nodata). Валиден пиксель, где все каналы конечны и `0 < отражение <= 1.5`.
- Все каналы на одной сетке (ресемплинг B05/B11 до 10 м — задача предыдущего модуля).

## Контракт выхода (`out/`)

| Файл | Содержимое |
|---|---|
| `zones_<YYYY_MM_DD>.tif` | uint8, `0` — нет данных, `1` — сильный стресс … `N` — норма. Для M3 используйте 3 класса (по умолчанию): 1 сильный, 2 умеренный, 3 норма |
| `hidden_stress_<YYYY_MM_DD>.tif` | uint8, `1` — скрытый стресс, `0` — нет, `255` — нет данных |
| `indices_<YYYY_MM_DD>.tif` | float32, 4 канала: NDVI, NDRE, MSAVI2, NDMI (с `--save-indices`) |
| `indices_summary.json` | статистика по каждой дате (ниже) |

Геопривязка (CRS, шаг, начало координат) копируется из входной сцены.

Структура JSON (`dates.<YYYY-MM-DD>`): `grid` (размер, `pixel_area_m2`, `crs_epsg`), `valid_pixels`, `valid_fraction`,
`indices.<имя>` (`n, mean, std, min, max, p5, p25, p50, p75, p95`), `zones` (`n_classes`, `classes[]` с `class, label, pixels, fraction, area_ha, mean{индекс}`),
`hidden_stress` (`pixels, fraction, area_ha, mean{индекс}, mean_z_ndre, mean_z_ndvi`), `files`. Если сцена не обработалась, вместо этого будет поле `error`, остальные даты считаются дальше.
`area_ha` — `null`, если CRS не проекционная в метрах.

## Как это работает

1. **Индексы** (`indices.py`): NDVI, NDRE, MSAVI2, NDMI по формулам каталога Awesome Spectral Indices; невалидные пиксели — NaN.
2. **Скрытый стресс** (`early_stress.py`): NDRE и NDVI сглаживаются (σ=1 px), переводятся в робастный z-score относительно самого поля на эту дату. Флаг — NDRE заметно ниже нормы (`z <= -1.5`) при ещё нормальном NDVI (`z > -1.0`). Если есть предыдущая дата, добавляется временное условие: падение аномалии NDRE между датами при почти неизменной аномалии NDVI. Мелкие пятна (< 12 px) убираются.
3. **Зоны** (`zoning.py`): признаки сглаживаются, стандартизируются, KMeans (k задан или по силуэту в 3–5), классы упорядочиваются по среднему z-композиту, затем мажоритарный фильтр и слияние пятен < 25 px с соседом.

## Ограничения и допущения

- **Зоны относительные.** Класс 1 — «хуже остального поля на эту дату», а не абсолютный порог. На полностью здоровом поле алгоритм всё равно выделит классы (разброс почвенной неоднородности), поэтому подписи «острый стресс» стоит читать вместе со средними индексами класса в JSON. Номера классов между датами не гарантируют одинаковый смысл.
- **Скрытый стресс тоже относительный:** если угнетена больше половины поля, медиана смещается и метод занижает очаги.
- Пороги (`z_ndre_thr`, `ndvi_min_scale` и др. в `EarlyStressConfig`) подобраны на синтетике и **не калибровались на реальных снимках**; их нужно подстроить по размеченным полям.
- Проверено на синтетической сцене (`synthetic.py`) и юнит-тестах; на реальных Sentinel-2 не запускалось.
- Бэкенд `spyndex` (`--backend spyndex`, `compare_with_spyndex`) написан по документации, но в среде разработки пакет не был установлен, поэтому не запускался. Основной расчёт на NumPy.
